# T1 — Cadence and queue runner

- **Wave:** 10
- **Lane:** operations
- **Recommended model tier:** code
- **Mode:** build
- **Dependencies:** none

## Objective

Compute the state of the operating loop the weekly cadence defines, instead of leaving a maintainer to derive it by hand.

## Read

- `AGENTS.md`
- `CONTEXT.md`
- `DECISIONS.md`
- `NON_GOALS.md`
- `QUALITY_BAR.md`

## Owned outputs

- `ops/cadence.yaml`
- `scripts/cadence.py`
- `tests/test_cadence.py`
- `handoffs/T1.md`

## Scope rule

This is a build task. Change only the owned outputs and the handoff.

## Requirements

- Encode only the passes and queues `ops/WEEKLY_CADENCE.md` defines, citing the section each came from.
- Report due passes, blocked handoffs, open gates and holds, and stale as-of dates.
- Reuse the staleness rule in `scripts/check_links.py` rather than restating it.
- Degrade to a stated unknown outside a git checkout.

## Acceptance

- [ ] The report exits 0 regardless of what it finds; only a configuration or usage error exits non-zero.
- [ ] The report states that it reads Git and knows nothing about Buzz activity.
- [ ] Unit tests cover the due rules, each queue, and the no-git path.
- [ ] `python3 scripts/validate.py --task T1 --root .` passes.
- [ ] `handoffs/T1.md` records status, validation, decisions, risks, and deferred opportunities.
- [ ] The worktree is committed and clean.

## Stop conditions

Stop and write a `BLOCKED` handoff rather than guessing when a locked decision conflicts with this task, a current claim cannot be verified, required evidence is unavailable, or completing the task requires editing an unowned path.
