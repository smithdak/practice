# F004 — Define governance

- **Wave:** 1
- **Lane:** foundation
- **Recommended model tier:** balanced
- **Mode:** build
- **Dependencies:** None

## Objective

Create lightweight, credible governance for an initially founder-led open-source community that can broaden over time.

## Read

- `AGENTS.md`
- `CONTEXT.md`
- `DECISIONS.md`
- `NON_GOALS.md`
- `QUALITY_BAR.md`

## Owned outputs

- `community/GOVERNANCE.md`
- `handoffs/F004.md`

## Scope rule

Modify only the owned output paths and the handoff file.

## Requirements

- Define founder, maintainer, contributor, and Practitioner responsibilities.
- Define decision categories and approval paths.
- Define how governance evolves based on demonstrated contribution.
- Include conflict-of-interest, removal, and succession mechanisms without bureaucracy.

## Acceptance

- [ ] Founder authority is explicit at launch.
- [ ] Contribution can earn responsibility through transparent criteria.
- [ ] Irreversible and policy decisions remain human-owned.
- [ ] `python3 scripts/validate.py --task F004 --root .` passes.
- [ ] `handoffs/F004.md` records status, validation, decisions, risks, and deferred opportunities.
- [ ] The worktree is committed and clean.

## Stop conditions

Stop and write a `BLOCKED` handoff rather than guessing when a locked decision conflicts with this task, a current claim cannot be verified, required evidence is unavailable, or completing the task requires editing an unowned path.
