# F005 — Define contribution system

- **Wave:** 1
- **Lane:** foundation
- **Recommended model tier:** balanced
- **Mode:** build
- **Dependencies:** None

## Objective

Make contributing easier than creating a polished artifact from scratch while maintaining quality.

## Read

- `AGENTS.md`
- `CONTEXT.md`
- `DECISIONS.md`
- `NON_GOALS.md`
- `QUALITY_BAR.md`

## Owned outputs

- `CONTRIBUTING.md`
- `community/CONTRIBUTION_MODEL.md`
- `handoffs/F005.md`

## Scope rule

Modify only the owned output paths and the handoff file.

## Requirements

- Define contribution paths from correction through maintained Project.
- Describe issue, branch, review, evidence, attribution, and release flow.
- Define recognition based on usefulness rather than volume.
- Include a first-contribution path for non-engineers.

## Acceptance

- [ ] A newcomer can select and complete a contribution path.
- [ ] The process supports Buzz discussion and Git review without duplicating source of truth.
- [ ] Acceptance and rejection criteria are explicit.
- [ ] `python3 scripts/validate.py --task F005 --root .` passes.
- [ ] `handoffs/F005.md` records status, validation, decisions, risks, and deferred opportunities.
- [ ] The worktree is committed and clean.

## Stop conditions

Stop and write a `BLOCKED` handoff rather than guessing when a locked decision conflicts with this task, a current claim cannot be verified, required evidence is unavailable, or completing the task requires editing an unowned path.
