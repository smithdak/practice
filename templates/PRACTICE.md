# Practice title

## Outcome

State the observable output, decision, or changed workflow this method produces.

## Problem and scope

Name the defined problem, context, and boundary. State what this Practice does not cover when that prevents misuse.

## Use when

List the conditions that make this method appropriate.

## Inputs

List the information, tools, permissions, and human roles required. Do not include secrets or confidential data.

## Method

1. Write the repeatable steps in order.
2. State each handoff, judgment point, or review point.
3. Name the expected output of the method.

## Evaluation

For a proposed Practice, state the trial, criteria, and acceptable result. For a tested or verified Practice, state the checks, criteria, and observed result. Do not report an unmeasured result.

## Implementation

Required for tested and verified Practices. Record the concrete setup details needed to apply the method within its stated scope.

## Failure modes

Required for tested and verified Practices. State failures observed or deliberately tested, their consequence, and the prevention, recovery, or escalation path. A proposed Practice may list anticipated failures clearly as hypotheses.

## Evidence

Required for tested and verified Practices. Link or describe the safe-to-share evidence record: context, method version, evaluation result, limitations, and the evidence-quality classification. Do not expose confidential inputs.

## Variations

Optional. Describe only variations that preserve the stated outcome, or link to a separate Practice.

## Deprecation notice

Required only when `maturity: deprecated`. State the deprecation date and reason, any safety or accuracy concern, and a replacement only if one exists.

## Changelog

Record dated, meaningful changes to the method, evidence, scope, or maturity.
