## Summary

Replaced the Steward's unobservable posting condition with a checkable one, and
gave it evaluation cases.

The profile granted a reply "when appropriate" and a draft "when posting is
ambiguous or consequential". The Steward is the only Practice agent with a write
surface, so that clause was the one bound that mattered most, and no reviewer or
evaluation case could separate a correct reply from one that should have been
withheld. This closes finding 2 of `release/PHASE3_REPORT.md`, which worker V1
raised when it could not write an observable case against the clause.

The replacement is seven numbered conditions decided from the request and the
reply. The Steward posts only when all seven hold; otherwise it drafts for a
human and names the failed condition by id. Naming the condition is part of the
output, which is what makes a withheld reply reviewable and a case assertable.

## Decisions made

- The test lives in the profile rather than the registry, because it governs the
  agent's behavior and the registry records bounds. The registry cites it.
- A case where posting is correct is required alongside the refusal cases. A
  test only a refusal can pass is unfalsifiable in the permissive direction, and
  an agent that never posts is not the fix.
- `behavior.post-or-draft` is available, not required, for every suite. Adding
  it to the required set would force four agents with no write surface to write
  cases about a bound they cannot reach.
- Multiple failures name the lowest-numbered condition rather than all of them,
  so the output is deterministic enough for a case to assert.

## Risks or unresolved questions

- **The cases are defined and unrun.** No agent is enabled; owner gate 6 remains
  open. A checkable condition is not evidence that the Steward respects it.
- `P3` and `P5` are decided from the drafted reply, so an agent that drafts a
  reply which quietly omits a policy statement can pass `P3` while giving a
  worse answer. The test bounds what may be posted, not whether the reply is
  good.
- The five undefined profile terms recorded in `release/PHASE3_REPORT.md`
  finding 3 are untouched, and one of them, "internal reasoning", still appears
  in this profile.
