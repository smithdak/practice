## Summary

Added `.github/workflows/ci.yml`, the PR/push CI workflow that fulfills the
recorded B011 deferral: unit tests, release validation, skill-eval structure
validation, and the link check run automatically on every pull request and
push to `main`. One job on `ubuntu-latest` with `actions/checkout@v4` and
`actions/setup-python@v5` (python `3.x`), running:

1. `python3 -m unittest discover -s tests`
2. `python3 scripts/validate.py --release`
3. `python3 skills/evals/validate.py --root .`
4. `python3 scripts/check_links.py`

No scheduled triggers, no secrets, workflow-level `permissions:
contents: read`, and `timeout-minutes: 10`. `scripts/check_links.py` is
produced by A2; by merge time it exists, so the workflow references it as a
normal step with no existence guard.

## Decisions made

- Trigger shape mirrors the existing `validate.yml` (`pull_request:` plus
  `push: branches: [main]`) so the two workflows stay consistent.
- No `pip install` step: `scripts/validate.py`, `skills/evals/validate.py`,
  and the test suite are stdlib-only (verified by import scan), so the
  workflow stays minimal.
- Python `3.x` per task spec rather than `validate.yml`'s pinned `3.12`.
- The A2 ordering note is recorded here only, not as a workflow comment, per
  repo style.
- Commit intentionally not run: the task's hard rules forbid git add/commit.

## Risks or unresolved questions

- Until A2 (`scripts/check_links.py`) merges, step 4 fails and the whole CI
  job is red on affected runs. This is intended sequencing; merging A2 first
  (or alongside A4) resolves it. No fix-forward change is needed in this file.
- `tasks/manifest.json` does not yet contain the Phase 2 task IDs, so
  `validate.py --task A4` cannot run for this task; the manifest-wiring task
  should land before integrators rely on task-level validation for A4.
- The job runs on both `push` to `main` and `pull_request`, so a PR branch
  based on `main` triggers two runs per commit; this duplicates the existing
  `validate.yml` behavior and is accepted as repo convention.
- The workflow has not run on GitHub yet; first live run should be checked
  after merge (local validation covers parsing and steps 1–3, not runner
  behavior).
