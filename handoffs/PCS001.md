## Decisions made

- Used `PCS001` as the local handoff and commit identifier for the user-assigned Practice Core Skills plan; did not represent it as a registered launch swarm task.
- Kept runtime directories flat under `.agents/skills/` and stored categorization and lifecycle data in `skills/catalog.yaml`.
- Kept all five skills instruction-only. Deterministic catalog, provenance, and eval-shape checks live in the separate eval validator; `scripts/taskctl.py` remains authoritative for swarm operations.
- Marked the first three skills as public distribution candidates and the two Practice repository operations skills as repository-only.
- Omitted optional `agents/openai.yaml` files and plugin packaging until behavioral evidence supports presentation and distribution decisions.
- Recorded the current Codex discovery and packaging claim from official OpenAI documentation, checked 2026-08-31: `https://learn.chatgpt.com/docs/build-skills`.

## Risks or unresolved questions

- No model behavior runs have been performed. Activation precision, behavioral compliance, and cross-model consistency remain unverified, so every skill is experimental.
- Catalog ownership currently names the governance role `practice-maintainers`; stable promotion requires a named human maintainer to accept responsibility.
- Task-scoped launch validation cannot recognize PCS001 unless a future post-launch task registry includes it. Adding it to the current launch manifest would conflict with the supplied scope and the repository rule against editing the manifest for this assignment.
- The official discovery and packaging behavior is current as of 2026-08-31 and can change; the README requires source re-checking when that behavior matters.
