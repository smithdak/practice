## Summary

Defined the canonical Lab template and schema, then added a proposed first Lab for comparing low-cost model configurations on three fixed synthetic artifact tasks. The experiment freezes prompts and conditions, scores task-completion quality with blinded review, captures direct request cost separately, and contains no model selection or result claim.

## Decisions made

- Used separate `status` and `result_status` fields so a proposed or completed Lab is not confused with the evidence currently recorded.
- Defined a run as one candidate configuration on one task in one trial; the first Lab requires three trials per task and candidate.
- Defined “low-cost” operationally through a predeclared direct-request cost ceiling and a captured provider price source, instead of naming or ranking models before execution.
- Kept cost as a separate gate from task-completion quality; the Lab does not calculate a composite quality-cost score.
- Used public synthetic packets so the full task set, rubric, and expected conditions can be reproduced without confidential inputs.

## Risks or unresolved questions

- The repository validator currently checks K013 output presence and links, not the new Lab front-matter, heading, or evidence-state invariants. The schema identifies suitable future mechanical checks.
- The cost ceiling and eligible candidate configurations must be chosen and recorded before execution; the proposed Lab intentionally does not assume current provider pricing or model availability.
- Model providers can change price, behavior, or hidden versions between runs. The execution record must retain the accessed price source, timestamp, and supplied configuration identifier.

## Deferred opportunities

- Add schema-aware validation for Lab metadata, ordered headings, result-state compatibility, and completed-run ledger fields when a task owns the validator.
- Add a safe-to-share execution-record template or machine-readable ledger after a completed Lab establishes which fields are useful in practice.
