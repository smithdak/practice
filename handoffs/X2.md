## Summary

Built the three records and the check that make "unattended within bounds" mean
something, and promoted nothing.

`ops/autonomy/operations.yaml` catalogs the five operations the phase plan names,
each with the fixed fields — command derived from the script that already
implements it, a narrow `write_scope`, a reversal, a blast radius, and the level
the operation is at today (A0 or A1). Two entries carry an empty write scope
because the scripts behind them write nothing; `release-brief-draft` carries a
deliberately incomplete command, because `scripts/release_brief.py` requires
`--since` and `--as-of` and both are per-run judgments no record binds. A catalog
entry may not declare A3 at all, so the catalog cannot promote anything.

`ops/autonomy/promotions.yaml` ships exactly as fixed: `schema_version: 1`,
`kill_switch: engaged`, `promotions: []`.

`scripts/autonomy_guard.py --operation <id> --root .` exits 0 permitted, 1
refused, 2 usage error. It permits only when all twenty-four preconditions hold
and prints one line per failure naming the precondition, the file, and the field.
The two independent records are separate preconditions: `kill-switch-released`
and `promotion-signed` fail independently, so a promotion with the switch engaged
is refused and a released switch with no promotion is refused. Against the
shipped repository all five operations refuse on exactly those two.

`ops/autonomy/README.md` explains the two records, tabulates every precondition,
states plainly that nothing is promoted and the switch is engaged, and records
how a promotion would be made and how it is reversed — reversal first by the
single edit that stops everything.

`tests/test_autonomy_guard.py` has 57 tests: one temporary-directory fixture per
refusal path, the safety-invariant test against the real repository, and one
fully signed fixture that must be permitted, so a guard that refused
unconditionally would fail rather than pass.

## Decisions made

- **The catalog cannot promote.** `operations.yaml` accepts levels A0-A2 only;
  `catalog-level` refuses an entry declaring A3. Combined with the two-record
  rule this means no single file grants an unattended run.
- **A write scope may never reach a governance record.** The guard refuses any
  glob covering `ops/autonomy/`, `scripts/`, `tests/`, `.github/`, `tasks/`,
  `buzz/agents/`, `docs/framework/`, `docs/schemas/`, `handoffs/`, `ops/ledger/`,
  or a named root record such as `DECISIONS.md`. An operation that can widen its
  own bound has no bound. Globs are compared with `fnmatch`, where `*` crosses
  `/`, so the containment check over-approximates rather than under-approximates.
- **Only a reserved-decision role may sign.** `signature-role` requires a role
  from the same controlled vocabulary `scripts/validate_agents.py` uses;
  `signature-authority` narrows that to `founder`, `beta-owner`, and
  `continuity-owner`, the roles `community/GOVERNANCE.md` and `ops/BETA_OPS.md`
  record as holding reserved decisions. A `maintainer` signature is refused.
- **The permanently ineligible list is read from the ladder at run time**, not
  only hardcoded. A list that has lost an entry the guard knows about refuses
  (`ladder-agreement`); an entry the ladder adds is honored without a code
  change. A missing section or an unparsable table is a refusal, following the
  house rule in `scripts/validate_agents.py` that an anchor it cannot find is a
  failure.
- **Record integrity is global, not per-operation.** A malformed promotion for
  some other operation, or one naming an uncatalogued or ineligible operation,
  refuses the operation being asked about too. A record that cannot be trusted in
  part is not trusted in whole.
- **`contract-drift-check` runs `scripts/validate_agents.py`** and its `note`
  records that the eval, packet, and artifact validators are separate commands
  not catalogued here, so a clean run is not evidence they pass. A single argv
  list cannot run several validators without a shell, and the catalog forbids
  shell metacharacters.
- **`cadence-snapshot` and `metrics-snapshot` share `ops/status/*.md`.** The plan
  fixes that scope for the first, and inventing a second generated-report
  directory for the other would have widened the surface for no gain. The
  directory does not exist today; a run would create it.
- **`release-brief-draft` writes only dated briefs.** Its glob
  `release/briefs/[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]-*.md` excludes that
  directory's README, so a run cannot rewrite the rule its own output is read
  under.
- **Added `--as-of` to the CLI** so signature-date checks are deterministic in
  tests. `--operation` and `--root` behave exactly as the plan fixes them.
- **Two optional catalog fields**, `level_basis` and `note`, mirroring
  `autonomy_basis` and `channel_note` in `buzz/agents/registry.yaml`. The
  promotion record takes the plan's seven fields and nothing else; an unknown
  field there is refused, because a misspelled field silently drops a bound.

## Risks or unresolved questions

- **CI wiring is unresolved and is not mine to fix.**
  `tests/test_contract_integration.py` requires every `scripts/*.py` to appear in
  `.github/workflows/ci.yml` or in `ValidatorWiringTests.EXEMPT` with a reason.
  Both files belong to W2 this phase, and X1's `scripts/ledger.py` trips the same
  test. The guard should be exempt rather than a CI step: its exit code is a
  decision about one operation, not a build verdict, and wiring it as a step
  would fail the build precisely because the substrate is inert. Suggested entry
  for W2: `"scripts/autonomy_guard.py": "decides one operation's permission and
  exits 1 when it refuses, which is the shipped state; the refusal invariant is
  asserted by tests/test_autonomy_guard.py"`.
- **`ops/autonomy/README.md` references `ops/autonomy/CANDIDATES.md` and
  `ops/autonomy/PROMOTION_PROPOSAL.md` as inline code, not as links**, because X6
  had not landed them when this task finished. If X6 completes, a later editor
  may turn them into links; if X6 does not, the link checker is unaffected.
- **The write-scope containment check is glob-shaped, not filesystem-shaped.** It
  proves a declared scope does not cover a governance path; it cannot prove a
  command respects its scope. That enforcement is X3's runner, and the two should
  agree on `fnmatch` semantics — the README and the catalog header state them.
- **`release-brief-draft` is catalogued with a command that exits 2.** That is
  deliberate and documented in its `note`, but a reader skimming the catalog
  could take it for a defect. The dossier is the place to argue the point.
- **The guard checks the signature, not the decision.** It cannot tell a real
  founder decision from a well-formed line of YAML. The record that makes the
  decision reviewable is the proposal named under `evidence`, and the guard only
  checks that the path resolves.
