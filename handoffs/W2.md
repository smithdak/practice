## Decisions made

- The self-modification exclusion is an eligibility rule rather than a new
  demotion trigger. A new trigger clause would have failed the demotion
  checker's bidirectional drift guard, and the guard already enforces the
  exclusion by refusing a write scope that could reach a governed path.
- The two write-scope matchers are deliberately left disagreeing. The guard asks
  whether a declared scope could reach a governed path and matches loosely; the
  runner asks whether a written path is inside scope and matches strictly. Both
  err toward refusing, and a comment says not to reconcile them.
- `maturity-promotion` replaced `merge` as the fixture operation in four test
  suites, rather than the fixtures being pinned to a literal list, so they keep
  testing the rule instead of the membership.
- Neither newly eligible operation was added to the catalog. Amendment 001 made
  them eligible; modelling bounded auto-merge and approved-content delivery as
  catalogued operations needs its own task, and a half-specified catalog entry
  would be worse than none.

## Risks or unresolved questions

- **Nothing has run unattended.** The permitted path has never executed against
  a real promotion, and no step of the scheduled workflow has run on GitHub.
- **`gh pr create` will fail** until an owner enables *Allow GitHub Actions to
  create and approve pull requests*.
- **The runner is not a sandbox.** It contains writes into a staging copy;
  absolute paths, `$HOME`, `/tmp`, and surviving child processes are not
  contained, and a pre-existing symlink out of the tree is an unclosed escape.
- **The A3 review-point trigger stays unevaluable** — no `review_point` field
  and no renewal record.
- **Scheduled refusals are durable only in GitHub log retention**, since the
  workflow appends no ledger entry for a refusal.

## Deferred opportunities

- Catalog entries modelling bounded auto-merge and approved-content delivery.
- A `review_point` field on a promotion, and a renewal record.
- A `--list` mode on the guard so the workflow need not parse the catalog.
- Real process isolation for the runner, and an enforced read scope.
- A repository-settings checklist for the owner before the first live dispatch.
- Wiring the demotion check into the unattended workflow as well as CI.
