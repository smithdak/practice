# T3 — Release brief generator

- **Wave:** 10
- **Lane:** release
- **Recommended model tier:** code
- **Mode:** build
- **Dependencies:** none

## Objective

Implement the pointer-checked draft method from Practice 005 as a generator over a commit range.

## Read

- `AGENTS.md`
- `docs/CONTEXT.md`
- `docs/DECISIONS.md`
- `docs/NON_GOALS.md`
- `docs/QUALITY_BAR.md`

## Owned outputs

- `scripts/release_brief.py`
- `tests/test_release_brief.py`
- `release/briefs/README.md`
- `release/briefs/2026-09-02-phase-2.md`
- `swarm/handoffs/T3.md`

## Scope rule

This is a build task. Change only the owned outputs and the handoff.

## Requirements

- Carry a repository path or a commit hash on every shipped line; omit anything unbacked.
- Read files with `git show` at the range head so a rerun reproduces the brief.
- Mark output a draft requiring human approval; never assert a maturity change or a cleared gate.
- Check generated text against the release token rules before writing it.

## Acceptance

- [ ] The committed Phase 2 brief matches a fresh run of the generator.
- [ ] An unknown revision or a non-checkout exits 1 and writes no partial file.
- [ ] Unit tests cover pointer-backing, omission, determinism, and every error path.
- [ ] `python3 scripts/validate.py --task T3 --root .` passes.
- [ ] `swarm/handoffs/T3.md` records status, validation, decisions, risks, and deferred opportunities.
- [ ] The worktree is committed and clean.

## Stop conditions

Stop and write a `BLOCKED` handoff rather than guessing when a locked decision conflicts with this task, a current claim cannot be verified, required evidence is unavailable, or completing the task requires editing an unowned path.
