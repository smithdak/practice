# B002 — Design end-to-end member onboarding

- **Wave:** 2
- **Lane:** buzz
- **Recommended model tier:** balanced
- **Mode:** build
- **Dependencies:** F001, F003, F005

## Objective

Move a new member from invitation through first useful contribution without requiring prior AI expertise.

## Read

- `AGENTS.md`
- `docs/CONTEXT.md`
- `docs/DECISIONS.md`
- `docs/NON_GOALS.md`
- `docs/QUALITY_BAR.md`
- `buzz/PLATFORM_SNAPSHOT.md`

## Owned outputs

- `community/ONBOARDING.md`
- `community/CAPABILITY_SELF_ASSESSMENT.md`
- `swarm/handoffs/B002.md`

## Scope rule

Modify only the owned output paths and the handoff file.

## Requirements

- Account for Buzz being invite-only.
- Define invitation, identity setup, orientation, capability self-assessment, first action, and follow-up.
- Create a self-assessment that routes to Learn, Use, Automate, Build, or Transform.
- Include agent-assisted and human-assisted paths.

## Acceptance

- [ ] A new member has one clear first action.
- [ ] Onboarding does not depend on unavailable automation.
- [ ] No private key handling is delegated to agents.
- [ ] `python3 scripts/validate.py --task B002 --root .` passes.
- [ ] `swarm/handoffs/B002.md` records status, validation, decisions, risks, and deferred opportunities.
- [ ] The worktree is committed and clean.

## Stop conditions

Stop and write a `BLOCKED` handoff rather than guessing when a locked decision conflicts with this task, a current claim cannot be verified, required evidence is unavailable, or completing the task requires editing an unowned path.
