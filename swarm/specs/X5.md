# X5 — Scheduled workflow that opens a pull request

- **Wave:** 15
- **Lane:** operations
- **Recommended model tier:** code
- **Mode:** build
- **Dependencies:** X3

## Objective

Fire a permitted operation on a schedule and deliver its result as a reviewable pull request.

## Read

- `AGENTS.md`
- `docs/CONTEXT.md`
- `docs/DECISIONS.md`
- `docs/NON_GOALS.md`
- `docs/QUALITY_BAR.md`

## Owned outputs

- `.github/workflows/unattended.yml`
- `ops/autonomy/PR_REVIEW_CONTRACT.md`
- `swarm/handoffs/X5.md`

## Scope rule

This is a build task. Change only the owned outputs and the handoff.

## Requirements

- Run the guard first and exit cleanly when nothing is promoted.
- Never push to the default branch and never force-push.
- Discover operations from the catalog rather than hardcoding a list.
- Request the minimum permissions that can open a pull request, and implement no auto-merge.

## Acceptance

- [ ] The writing job does not start while nothing is permitted.
- [ ] A refusal is the expected outcome today and does not look like a broken build.
- [ ] The review contract states that merging accepts the content, not the process.
- [ ] `python3 scripts/validate.py --task X5 --root .` passes.
- [ ] `swarm/handoffs/X5.md` records status, validation, decisions, risks, and deferred opportunities.
- [ ] The worktree is committed and clean.

## Stop conditions

Stop and write a `BLOCKED` handoff rather than guessing when a locked decision conflicts with this task, a current claim cannot be verified, required evidence is unavailable, or completing the task requires editing an unowned path.
