# Z4 — Staleness-sweep prerequisites

- **Wave:** 18
- **Lane:** operations
- **Recommended model tier:** strong
- **Mode:** revision
- **Dependencies:** X2, X6, Z1

## Objective

Build the three tooling prerequisites the `staleness-sweep` dossier says must exist before a promotion decision can be made on facts, and lay out the fourth, the overlap decision, as a packet a human can decide from. Decide nothing.

The dossier (`ops/autonomy/CANDIDATES.md`, "The decision, and what would have to exist first") names four things: a coverage number carried in the result itself; a recorded decision on the overlap with `cadence-snapshot`; a statement of what an unattended run does with a warning that does not change the exit code; and a named role who receives a stale finding and owns the disposition. The second is a human decision. The other three are tooling and records.

This is a revision task: it corrects files earlier tasks own. Change only the owned outputs and the handoff. `scripts/autonomy_guard.py`, the ladder, the workflows, the Makefile, `ops/status/`, and every dated record are not owned; if one must change, write a BLOCKED handoff naming the exact edit.

## Fixed interfaces

1. **Coverage in the result.** The sweep's output carries, on every run: markdown files scanned; files with at least one dated `As of:` line the rule can read; dated lines read; files that mention "as of" in a form the rule cannot date; stale dates; broken links. Print it as a labelled line a person reads and as one machine-readable summary line a workflow or ledger can carry. The cadence report's staleness section carries the same coverage numbers, computed through the same functions, so the two cannot disagree. A clean result must be impossible to read as "the repository is current": the coverage line appears whether or not anything is stale.
2. **A malformed date is reported, not crashed on.** A line the pattern matches whose date `date.fromisoformat` rejects is an error with file and line, and sets the exit code to 1, exactly as a broken link does. No traceback.
3. **The warning rule.** Write, in the catalog entry's `note` and in the dossier, what an unattended run does with a stale warning that does not change the exit code, under the catalogued command as it stands, and give the sweep an opt-in mechanism (a flag, default off, that CI does not pass) by which a caller can make a stale warning observable in the exit code without changing what the sweep reports. The rule must be consistent with the ladder's `stale_as_of` row: a stale date is a warning, deciding is the artifact maintainer's, and the sweep never edits a date or a link.
4. **The disposition owner.** Record, in the catalog entry's `note` and the dossier, the controlled role that receives a stale finding from an unattended run and owns its disposition, consistent with the stale-content queue's `human_owner_role` in `ops/cadence.yaml`. Role vocabulary only; no person.
5. **The overlap packet.** Replace the dossier's "The decision, and what would have to exist first" section with one that marks the three tooling prerequisites as existing, with where each is, and lays out the overlap decision as two options a human can choose between: fold the calendar half into `cadence-snapshot`, or keep a separate operation. For each, state what one unattended run would leave behind, what a wrong output causes, and the facts that favour it. Recommend nothing; the dossier's job is to make the decision take minutes, not to make it.

## Requirements

- Re-measure the coverage numbers on the day you write them and date them; the dossier's 2026-09-02 numbers are examples of the shape, not facts to copy.
- Change no `maturity` or `evidence_quality` value, promote nothing, and assert no gate or hold is cleared.
