## Objective

Replace five profile terms that a guardrail depends on with definitions decidable from the record, and give each a checkable evaluation case, so a reviewer can tell a compliant reply from one that only sounds compliant.

## The five terms

Recorded in `swarm/reports/PHASE3_REPORT.md` finding 3 and `swarm/handoffs/V1.md` (Risks):

1. **Steward, "internal reasoning"** — `buzz/agents/STEWARD.md`, Prompt-injection handling. Has no observable definition for a text-producing agent.
2. **Librarian, "safe-to-share" and "approved-to-share thread"** — `buzz/agents/LIBRARIAN.md`, used four times across source eligibility, classification rules, and quoting, with no checklist; who approves and in what recorded form is unstated.
3. **Release Editor, "maintainer-confirmed record"** — `buzz/agents/RELEASE_EDITOR.md`, Completion gate. No shape is given, so a chat message asserting the same thing cannot be told apart from a record.
4. **Research Auditor, "when authorized"** — `buzz/agents/RESEARCH_AUDITOR.md`, Allowed. The registry defers authorization to a human decision recorded at enablement; the profile never says what that record must state.
5. **Guide Maintainer, "the assigned workspace"** — `buzz/agents/GUIDE_MAINTAINER.md`, Scope and eligible inputs. The registry says a human supplies workspace paths at enablement; the profile never says how the assignment is recorded or what happens at its edge.

## The pattern

Y1 replaced "when appropriate" with seven numbered conditions decided from the request and the reply, and required the output to name the failed condition by id. Do the same here: a definition is a set of conditions decided from things in the record — the request, the drafted reply, a registry field, or a human-written record with a stated shape and location — not from the agent's judgment. Name what makes each condition fail. Where a definition rests on a record a human supplies at enablement (an authorization, a workspace assignment, a sharing approval), define the record's required contents and where the agent cites it, and define the default when it is absent: deny, hold, or escalate.

## Fixed interfaces

- Each definition lives in the profile that uses the term, in the section where the term first appears or in a short named subsection, and every later use of the term refers to that definition. Replace loose synonyms with the defined term.
- A definition may not widen what an agent may do. Each must be at least as restrictive as the current prose read conservatively. Where the current prose is ambiguous between a permissive and a restrictive reading, take the restrictive one and say so in the handoff.
- Registry: where an `enablement_prerequisites` item already defers a decision to a human (the auditor's authorization, the Guide Maintainer's workspace paths, the Librarian's sharing approval), cite the profile's definition of what that record must contain. Leave every controlled value unchanged.
- Evaluation cases: at least one `behavior` case per term whose `expected` line asserts the definition observably, and, for each definition that can permit as well as refuse, one case where the permitted path is correct. A test only a refusal can pass is unfalsifiable in the permissive direction. Use existing kinds where they fit; add a kind only if none fits, and document it in the README. Adversarial cases stay `severe`.
- Leave every suite's `profile_basis.source_commit` and `reviewed` untouched. The Director refreshes them at integration once the commit exists.
- Finding 4 of the Phase 3 report (partial compliance with an injected instruction) is not in scope. Record it under Deferred opportunities.
