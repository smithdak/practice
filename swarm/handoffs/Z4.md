## Summary

Built the three tooling prerequisites the `staleness-sweep` dossier said had to
exist before a promotion decision could be made on facts, and rewrote the
dossier's decision section as a two-option packet for the overlap with
`cadence-snapshot`, which is the fourth prerequisite and a human decision.
Nothing is promoted; the catalogued command did not change; the guard still

The work was started by a worker that was interrupted twice by transient
server errors after finishing the two scripts. The Director completed the
tests, the catalog prose, the dossier, and this handoff from the state on disk.

**Coverage in the result.** `scripts/check_links.py` now reads every `As of:`
line once through `scan_as_of`, buckets every markdown file as dated,
undatable (mentions "as of" but yields no readable date), or silent, and prints
the coverage twice on every run: an `As-of coverage:` sentence for a person and
a final `check_links_summary:` line of `key=value` counts that a workflow or a
ledger's stdout excerpt can carry, with `parse_summary_line` to read it back.
`scripts/cadence.py` computes its staleness section through the same function
and prints the same sentence, and its JSON summary gains `as_of_dated_files`,
`as_of_files_scanned`, and `malformed_as_of_dates`.

**A malformed date is an error, not a crash.** `As of: 2026-02-30` is reported
as `path:line: malformed as-of date ... (not a calendar date)` on stderr and
sets the exit code to 1, ordered after a file's link errors. It counts the file
as undatable, not dated.

**The warning rule.** `--fail-on-stale` is opt-in and off by default; CI and the
catalogued command pass no flag; it changes the exit code alone, and the output
is byte-identical with and without it. The catalog entry's `note` states what an
unattended run does with a stale warning under the command as catalogued (exits
0, outcome `completed`, finding carried in the summary line the ledger excerpt
and pull request body show) and that a proposal wanting a stale date to fail
the run must add the flag to the command, which is a change to the entry a
proposal names.

**The disposition owner.** The `note` and the dossier name the
`artifact-maintainer` role, consistent with the stale-content queue's
`human_owner_role` in `ops/cadence.yaml`, which did not need to change.

**The overlap packet.** The dossier's last section lays out Option A (withdraw
the operation; the cadence report already carries the section) and Option B
(keep a separate operation, with or without the flag), each with what one run
leaves behind, what a wrong output causes, and the facts that favour it. It
recommends nothing.

## Decisions made

- **Coverage buckets are exclusive and exhaustive.** A file is dated if the rule
  read at least one calendar date from it, else undatable if it mentions "as of"
  anywhere outside code, else silent. A malformed date makes a file undatable,
  because the rule read no date from it.
- **The summary line is the last line of stdout**, so the runner's tail excerpt
  always carries it whatever `OUTPUT_EXCERPT_LINES` is.
- **`blast_radius` was edited although the spec listed only `summary`, `note`,
  and `level_basis`.** It stated that the sweep exits non-zero only on a broken
  link, which became false when a malformed date began to fail the run. A
  Director decision, recorded here.
- **The at-a-glance row and the unattended description were updated** for the
  same reason: they described an exit-code rule the sweep no longer has.
- **The flag is named `--fail-on-stale` rather than an exit-code argument**, so
  the choice a proposal makes is binary and readable in the catalogued command.
- **`ops/cadence.yaml` was not changed.** Its stale-content queue already names
  the artifact-maintainer role as owner; the catalog note now cites it.

## Risks or unresolved questions

- **No unattended run has produced a stale finding**, so the disposition
  practice the role owns is unobserved. The role is named; nothing shows a
  person acting in it.
- **The coverage sentence cannot make anyone read it.** A reader who stops at
  "0 stale as-of date(s)" still takes a clean sweep for a current repository.
  The dossier says so.
- **The runner's stdout excerpt is a tail.** If a future sweep prints more lines
  after the summary line, the ledger loses the counts. Nothing enforces the
  ordering except `main` and the test that checks it.
- **The overlap decision is unmade**, and the dossier's Option A would withdraw
  a catalogued operation, which is a change to `ops/autonomy/operations.yaml`
  through the reserved-decision path.

## Deferred opportunities

- **Carry the summary counts as structured ledger fields** rather than as a
  stdout line, once a run exists to record; that is a ledger schema change.
- **A per-file list of undatable mentions**, so a maintainer can convert
  currency claims the rule cannot see into dated lines it can.
- **Extending the rule's pattern** to date phrasings such as "based on the
  verified platform snapshot as of 2026-09-01", which the dossier records as
  invisible today; a pattern change alters what every prior run would have
  counted and is worth its own task.
