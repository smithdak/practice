## Decisions made

- Kept all calls within the launch-safe CLI surface: channel list/create/topic/purpose, canvas set, and message get/send.
- Replaced the unowned persistent report file with a JSON report on standard output so relay and credential context are not stored by the bootstrapper.
- A create conflict triggers one safe channel re-list to tolerate a concurrent successful bootstrap; no destructive recovery is attempted.

## Risks or unresolved questions

- Seed idempotency is deliberately bounded to the latest 100 messages, the launch-safe CLI limit used by the bootstrapper. If a marker falls outside that history, a maintainer must inspect and resolve any duplicate manually.
- A real hosted-relay apply was not run in this worktree because it requires an authorized local Buzz identity and relay environment variables.
