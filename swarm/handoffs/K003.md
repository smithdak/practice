## Decisions made

- Set the Guide's primary completion capability to `automate`: every route must produce a bounded, repeatable, human-reviewed workflow. Build and Transform are secondary capabilities that require their route-specific evidence rather than being implied for every Practitioner.
- Used one six-module common spine with route overlays instead of three separate curricula. Every route crosses the same universal checkpoints; the route changes exercise depth and the final extension.
- Made Modules 1–4 an explicitly interim starter path using embedded evidence worksheets, so work can begin before downstream module and Practice artifacts are published without implying full Guide completion.
- Listed planned downstream module and Practice paths as code rather than live links. This avoids broken links and false claims that unpublished artifacts are available; the existing Practice index remains the current canonical reference.
- Separated the optional Frontier Studio from core completion. Its output is a bounded Lab or research brief, not an established Practice or production recommendation.
- Required claims to trace to local evidence and kept completion distinct from universal reliability, production readiness, certification, business impact, or permission to expand autonomy.

## Risks or unresolved questions

- The Guide remains `draft` because six module files and three named Practices are downstream tasks and have not yet been reviewed as one end-to-end path.
- Planned module and Practice references are not live links. Guide maintainers must replace them after those exact artifacts exist and pass review.
- The repository validator checks output presence and relative links but does not enforce Guide metadata, canonical heading order, module contracts, or route/evidence coherence; these received a manual review only.
