## Summary

Created the Note and Project artifact schemas and their fill-in templates,
completing the B008 deferral for Note and Project canonical formats. The Note
schema defines a bounded-observation record with an evidence-honesty bar ("an
observation is not a measurement"), an `observation → validated →
promoted/withdrawn` maturity path, and an explicit Note→Practice promotion
route in which the Note's anecdote motivates a proposal but never constitutes
trial evidence. The Project schema records `proposed → active → paused →
retired` lifecycle states with named stewardship as the gate to `active`, maps
its required sections to the existing GitHub Project intake form fields, and
draws the experiment-versus-maintained-software boundary against Labs. Both
templates cross-link their schemas, the Knowledge Taxonomy, and the
contribution model.

## Decisions made

- Note `maturity` uses `observation`, `validated`, `promoted`, `withdrawn` —
  lifecycle language a Note can honestly carry. `promoted` and `withdrawn` are
  terminal and retained for history, matching house deprecation behavior.
- Task-mandated field names kept verbatim: Note uses `date` and
  `author-role`; Project uses `name`, `repo_url`, `maintainers-role`, and
  `associated-capability`. `author-role` is one controlled role value naming
  the observation's work context, not a credential. `maintainers-role` is a
  `Name (role)` list because stewardship requires named accountability that a
  role tag alone cannot carry.
- A Note promoted to a Practice starts that Practice at
  `evidence_quality: none`: an unstructured observation is not an application
  of a stated method, so it cannot be the `single-run` trial record.
- Project lifecycle uses `retired` (matching CONTRIBUTING.md stewardship
  verbs: pause, transfer, retire) rather than the `deprecated` state used by
  content artifacts.
- Project `license` defaults to `Apache-2.0` (the code license default per
  docs/DECISIONS.md and LICENSES.md), not the CC BY 4.0 content default.
- Added required `created` to Project front matter (house convention); the
  Note stays on the task's minimal `date` field with a Changelog required only
  after it leaves the initial `observation` state, keeping the Note the
  lightweight entry point of the contribution ladder.
- Project required sections map to intake form field ids:
  `problem` → `Problem`, `smallest_release` → `Smallest useful release`,
  `approach` → `Approach and boundaries`,
  `evidence` → `Evidence and success check`, `stewardship` → `Ownership`.

## Risks or unresolved questions

  validator can enforce" sections are specifications for a future extension of
  `scripts/validate_artifacts.py` (A1), not current checks.
- The `maintainers-role` `Name (role)` composite format is a new convention
  with no controlled vocabulary for project roles; a later decision could
  replace it with structured fields.
- G2 is absent from `swarm/manifest.json`, so output-ownership and
  handoff-status checks do not cover this task until wiring lands.
