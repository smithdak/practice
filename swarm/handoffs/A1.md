## Summary

Added `scripts/validate_artifacts.py`, a deterministic, offline, stdlib-only
schema validator for Practice, Guide, Lab, and Story markdown artifacts, plus
45 unit tests in `tests/test_validate_artifacts.py` built entirely from
tempfile fixtures. The validator parses the YAML-ish front matter subset the
schemas use (scalars, quoted strings, flow lists, block lists, `null`),
checks required fields, controlled vocabularies, semver versions, ISO dates
(`updated` not before `created`), known licenses (CC-BY-4.0, Apache-2.0),
artifact/directory agreement, maturity/status-to-evidence pairings,
conditional fields (`last_verified`, `deprecated_on`, `deprecation_reason`),
and schema-defined headings (order enforced for Guides and Labs). A Practice
claiming `maturity: tested` (or `verified`) must reference a Lab or
`evidence/` record in its body — Wave E can now rely on this gate. All
errors are `path:line: message` against repo-relative paths.

## Decisions made

- **Guide modules vs full Guides.** `guides/ai-native-practitioner/NN-*.md`
  modules carry no front matter in this repository and are not full Guide
  artifacts, so they are validated leniently: a `# ` title is required, and
  if front matter is present, `artifact_type` (when set) must be `guide` and
  any present controlled fields are validated. The flagship Guide itself
  lives at `guides/ai-native-practitioner/README.md` with full front matter
  and is validated against the complete GUIDE_SCHEMA, including canonical
  heading order. Non-module `guides/` files without front matter
  (`CURRICULUM.md`, index READMEs) are treated as index documents and
  skipped; within `practices/`, `labs/`, `stories/`, any `*.md` other than a
  bare `README.md` must be an artifact with front matter.
- **Directory/type agreement is authoritative.** `artifact_type` must equal
  the directory's type (including READMEs that carry front matter); a
  mismatch reports one actionable error and skips type-specific checks to
  avoid cascading noise.
- **License check.** Enforced as membership in {CC-BY-4.0, Apache-2.0} per
  the task invariant and docs/DECISIONS.md defaults; the schemas additionally
  name CC-BY-4.0 as the content default, which all current artifacts use.
- **Deprecated evidence.** Per PRACTICE_SCHEMA, a deprecated Practice may
  keep any `evidence_quality` (including `none`), so the maturity/evidence
  pairing permits all levels only for `deprecated`.
- **Heading enforcement.** Order is enforced where the schema states it
  (Guides and Labs); presence only where it does not (Practice sections by
  maturity, Story sections). Story `Before`/`After`/`Result` must have
  non-empty content. Extra sections (e.g. `Variations`) are allowed.
- **Fenced code is masked** (line-count preserving) before heading, section,
  and evidence-reference scans, because guide modules legitimately contain
  `##` lines inside code fences.
- **Lab `last_run`** is excluded from the generic required-field emptiness
  check and validated by the `result_status` pairing instead (`null` only
  for `not-run`).

## Risks or unresolved questions

- `scripts/validate.py --root .` currently fails on
  `Broken relative link: swarm/handoffs/R2.md -> …` — a literal `…` placeholder in
  R2's handoff. That file is owned by another task; the owner or the
  Director should fix or finalize it before release validation.
- The tested/verified "linked trial" check accepts a body reference matching
  `labs/…` or `evidence/…` (link or plain path). A tested Practice whose
  evidence lives elsewhere (e.g. an external URL only) would need the schema
  or this rule revisited; today nothing in the repo claims tested maturity.
- The Lab schema's "not-run Labs contain no claimed result" rule (no numeric
  scores in `Results`/`Interpretation`) is not mechanically enforced; a text
  heuristic would false-positive on rubric examples and needs a stricter
  convention first.

## Deferred opportunities

- Front matter for Guide modules (title, capability, module-level metadata)
  would let A1 enforce module-level invariants; G1 owns guide prose, so this
  needs a schema decision first.
- Mechanically checking the not-run Lab rule above once the repo agrees on a
  pending-state marker convention for `Results`/`Interpretation`.
- Run-ledger structural checks for `partial`/`complete` Labs (one record per
  run, output hash, cost fields) once real run data exists (Wave E outputs).
- `Note` and `Project` artifact support once G2 defines their schemas.
